## KRİTİK — sömürülebilir, bugün açık

### K1. Yetki yükseltme: saha sorumlusu kendini ilçe yönetimi yapabiliyor
`app/api/hesap-ekle/route.js` — `PATCH`

`yetkiVar()` çağıranı `il_yonetimi, ilce_yonetimi, sorumlu, koordinator`
rollerinden biri olarak kabul ediyor. `POST` bunu `isAdmin` ile ayrıca
denetliyor, **`PATCH` denetlemiyor**:

```js
if (!(await yetkiVar(a, token))) return ... 403   // rol ayrımı YOK
const { id, rol } = await req.json();
const gecerli = [...GENEL_ROLLER, ...BLOK_ROLLER].includes(rol) ? rol : null;
upd.rol = gecerli;
await a.from("profiles").update(upd).eq("id", id);   // service_role → RLS baypas
```

`GENEL_ROLLER` içinde `ilce_yonetimi` var. Yani herhangi bir `sorumlu`, kendi
oturum token'ıyla tek bir `PATCH` isteği atarak kendini ilçe yönetimi yapabilir:

```
PATCH /api/hesap-ekle   { "id": "<kendi uid>", "rol": "ilce_yonetimi" }
```

Oradan sonra ilçenin tamamına yazma yetkisi kazanıyor. `id` alanı da
denetlenmiyor — başkasının rolü de değiştirilebilir, hedefin ilçesi de
kontrol edilmiyor (Başakşehir yönetimi başka ilçenin kullanıcısını düzenleyebilir).

**Düzeltme:** `PATCH` içinde `ADMIN_ROLLER.includes(caller.rol)` şartı; `rol`
listesinden `ilce_yonetimi`'nin yalnızca `il_yonetimi` tarafından verilebilmesi;
hedef profilin `ilce_id`'sinin çağıranın ilçesiyle eşleşmesi.

### K2. Hesap silme yetkisi saha rollerinde
`app/api/hesap-ekle/route.js` — `DELETE`

Aynı kök: `DELETE` de yalnızca `yetkiVar()` çağırıyor. Bir `sorumlu`,
**il başkanının hesabını silebilir**. Hedef ilçe kontrolü de yok.

Ek olarak silme eksik: `bolge.sorumlu_id`, `bolge.koordinator_id` ve
`sokak_ekip.profil_id` temizleniyor ama **`sokak_grup.baskan_id` temizlenmiyor**.
Bu FK'nın `ON DELETE` davranışı yok (NO ACTION), dolayısıyla grup başkanı olan
bir kullanıcıyı silmek FK ihlaliyle **başarısız oluyor**.

## ORTA

### O1. PostgREST filtre enjeksiyonu — arama kutusu
`app/components/SokakEkip.jsx:51`
```js
sorgu.or(`ad.ilike.%${q}%,soyad.ilike.%${q}%`)
```
`q` ham kullanıcı girdisi ve doğrudan filtre ifadesine gömülüyor. SQL enjeksiyonu
değil (PostgREST ayrıştırıyor) ama **filtre enjeksiyonu**: virgül/parantez içeren
bir arama ifadesi sorguyu bozar ya da ek koşul ekletir. Pratikte "Ali, Veli"
yazınca arama kırılır. `q` içindeki `,`, `(`, `)`, `.` karakterleri temizlenmeli.

### O2. `ziyaret` tablosunda `hane_id` benzersiz değil
Kod bir hanede en fazla bir ziyaret satırı varsayıyor
(`select id ... limit 1` → update, yoksa insert). Kısıt olmadığı için iki kişi
aynı anda kaydederse iki satır oluşur. `BaskanRapor`'un *"benzersiz ziyaret
edilen hane"* sayacı da aslında satır sayıyor (`count exact` üzerinde `distinct`
yok) — mükerrer oluştuğu anda oran şişer. Bugün 18 ziyaret var, 0 mükerrer;
saha başlayınca çıkar.

### O3. Eksik benzersizlik kısıtları

  açık; `auth.users` e-postayı benzersiz tutuyor ama `profiles` kopabiliyor.
- `kisi.tc_hash` → UNIQUE yok. **Üye listesi içe aktarma bunsuz güvenli değil**;
  aynı kişi her yüklemede tekrar eklenir.
- `sokak_ekip (grup_id, profil_id)` → UNIQUE yok. Aynı kişi bir gruba iki kez
  eklenebiliyor.
